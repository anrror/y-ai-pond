## 5. 关键技术决策

| 决策 | 选择 | 依据 |
|------|------|------|
| 边缘 AI 平台 | **RK3588** (首选) / Jetson Orin Nano (备选) | RK3588: ~100 FPS @ 6-10W, 性价比最优 |
| YOLOv8n 部署 | ONNX → RKNN (INT8) / TensorRT (FP16) | 平台原生加速，< 0.3 mAP 损失 |
| 投喂控制 | **Mamdani 模糊 + PID 混合** | 已验证 66.5% MSE 降低 vs PID |
| MQTT 协议 | **v5 + Protobuf + EMQX** | v5 原生会话保持，Protobuf 压缩3-5× |
| 时序 DB | **InfluxDB 3** (实时) + PostgreSQL (业务) | 无需新 DB 类型；ecosystem 复用 |
| ML 推理 | **Python 训练 → ONNX 导出 → onnxer Go 推理** | 零 CGO，零 Python 生产依赖 |
| 数字孪生 GNN | **D-TGCN** (有向图) + 动态邻接矩阵 | 水流方向物理先验，R²=0.884 |
| 前端框架 | **Next.js 15 + shadcn/ui** | 与 y-ai-gc 生态一致，Phase 2 |
| 部署方案 | **Docker Compose** (单机) → **Helm** (K8s) | 分级部署，平滑迁移 |

## 6. 风险矩阵与缓解措施

| 风险 | 严重程度 | 可能性 | 缓解措施 |
|------|---------|--------|---------|
| RK3588 NPU 推理延迟不达标 | HIGH | MEDIUM | Jetson Orin Nano 备选方案 (T8已支持双后端) |
| YOLOv8n 养殖场景精度不足 | HIGH | LOW | 可微调自定义数据集 (FeedFishDatas 7.4K images) |
| MQTT 弱网环境断线频繁 | MEDIUM | HIGH | 指数退避重连 + 7天本地缓冲 + DTN 模式 |
| 传感器生物附着导致精度漂移 | MEDIUM | HIGH | 每周校准 + 数据校验(范围检查) + 异常告警 |
| ST-GNN 训练数据不足 | HIGH | MEDIUM | 先用 LSTM 基准模型；GNN 作为高阶可选功能 |
| RL 策略在真实环境效果差 | MEDIUM | MEDIUM | 先在 DT 仿真环境验证；保守增量部署 |
| Go ONNX Runtime 兼容性问题 | LOW | LOW | onnxer 纯 Go 实现，零 CGO，可跨编译 |
