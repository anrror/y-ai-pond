## 2. MQTT 主题结构

### 2.1 主题树层级

```
pond/v1/{farm_id}/{pond_id}/
├── sensor/
│   ├── water/ph               ← float32, QoS 0
│   ├── water/do               ← float32, QoS 0
│   ├── water/temperature      ← float32, QoS 0
│   ├── water/nh3              ← float32, QoS 0
│   ├── water/turbidity        ← float32, QoS 0
│   └── water/level            ← float32, QoS 0
│
├── camera/
│   ├── inference              ← Protobuf InferenceResult, QoS 0
│   └── snapshot               ← JPEG (关键帧), QoS 0
│
├── control/
│   ├── feeding/status         ← Protobuf FeedingStatus, QoS 1
│   └── feeding/decision       ← Protobuf ControlDecision, QoS 1
│
├── device/
│   ├── status                 ← Protobuf DeviceStatus, QoS 1
│   └── alarm                  ← Protobuf Alarm, QoS 1

cloud/{farm_id}/{pond_id}/
├── cmd/
│   ├── feeding/start          ← JSON {speed, duration}, QoS 1
│   ├── feeding/stop           ← JSON {}, QoS 1
│   ├── aerator/on             ← JSON {}, QoS 1
│   └── aerator/off            ← JSON {}, QoS 1
│
├── config/
│   ├── fuzzy/update           ← JSON {rules[], mfs[]}, QoS 2
│   └── sensor/interval        ← JSON {ph, do, temp}, QoS 2
│
└── model/
    └── update                 ← JSON {version, url, sha256}, QoS 2
```

### 2.2 QoS 策略矩阵

| 数据类型 | QoS | 理由 |
|---------|-----|------|
| 传感器遥测 (pH/DO/Temp) | **0** | 可容忍丢包；下次读数覆盖上次 |
| 摄像头推理结果 | **0** | 高频发送；单帧丢失不影响决策 |
| 投喂状态/决策日志 | **1** | 至少一次送达；审计需要 |
| 设备心跳/告警 | **1** | 至少一次送达；接收端去重 |
| 云端控制指令 | **1** | 至少一次送达；电机指令幂等 |
| 配置/固件更新 | **2** | 必须精确送达一次 |

## 3. 数据流架构

### 3.1 上行数据流（边缘 → 云端）

```
ESP32-S3 (pH/DO/Temp/NH3/Turb)
      │ I2C / 1-Wire / Analog
      ▼
RK3588 Edge Controller
      │ ┌──────────────┐
      ├─┤ Sensor HAL    │  ← 读取传感器, 范围校验
      │ └──────────────┘
      │ ┌──────────────┐
      ├─┤ YOLOv8n       │  ← 摄像头帧推理
      │ └──────────────┘
      │ ┌──────────────┐
      ├─┤ Texture Extr  │  ← 摄食强度评估
      │ └──────────────┘
      │ ┌──────────────┐
      ├─┤ Fuzzy-PID     │  ← 投喂决策
      │ └──────────────┘
      │
      ├── Protobuf encode → MQTT Publish (QoS 0/1)
      │   pond/v1/{farm}/{pond}/sensor/water/{param}
      │
      └── SQLite local buffer (断网时)
               ↓ (恢复连接后补传)
     
EMQX Broker ──→ Go MQTT Gateway (autopaho subscriber)
                    │
                    ├── Protobuf decode → Validate
                    ├── InfluxDB 3 WritePoints (batch 5K-10K)
                    ├── PostgreSQL INSERT (feeding_logs)
                    ├── Redis HSET (device_shadow:reported)
                    └── Alert Engine → Check threshold
```

### 3.2 下行数据流（云端 → 边缘）

```
Web Dashboard / API
      │ POST /api/v1/devices/:id/shadow
      ▼
Go API Server
      │
      ├── Validate JWT + RBAC
      ├── Update PostgreSQL (desired state)
      ├── Compute delta = desired - reported
      │
      ├── MQTT Publish (QoS 1)
      │   cloud/{farm}/{pond}/cmd/feeding/{start|stop}
      │   cloud/{farm}/{pond}/config/{update}
      │
      └── Record audit log

EMQX Broker ──→ Edge Controller (autopaho subscriber)
                    │
                    ├── JSON decode
                    ├── Validate (不覆盖安全互锁参数!)
                    ├── 更新本地配置
                    ├── Execute (GPIO/PWM)
                    └── Report status (MQTT publish)
```

### 6.3 边缘端组件依赖

```
RK3588 Board
├── Go Binary (edge controller)
│   ├── YOLOv8n RKNN → NPU (6 TOPS)
│   ├── Fuzzy-PID → CPU
│   ├── MQTT Client → WiFi/Ethernet
│   └── SQLite → eMMC (7-day buffer)
│
├── Dependencies:
│   ├── librknnrt.so (Rockchip NPU driver)
│   ├── OpenCV (image preprocessing)
│   └── periph.io (GPIO/I2C/SPI)
│
└── Network:
    ├── Primary: WiFi/Ethernet → EMQX Cloud
    └── Backup: LoRa (Ra-02 SX1278) → sensor nodes
```

## 7. 关键性能指标

| 指标 | 目标 | 测量方法 |
|------|------|---------|
