## 1. 测试目标与范围

### 1.1 测试目标

本方案用于验证 y-ai-pond 边缘端在真实硬件上的适配性与稳定性，覆盖三大硬件平台：

1. **RK3588（首选主控）**：验证 YOLOv8n RKNN INT8 推理精度、延迟、功耗与散热。
2. **Jetson Orin Nano（备选主控）**：与 RK3588 做对比测试，确认备选平台可用。
3. **ESP32-S3（传感器节点）**：验证 pH/DO/Temp/NH3 传感器采集精度与校准仪器的一致性。

最终目标是确认边缘端在 7 天连续运行下保持稳定，指标满足 README 与硬件设计说明书中的规格要求。

### 1.2 测试范围

| 覆盖项 | 说明 |
|--------|------|
| YOLOv8n 模型精度 | RKNN INT8 量化 vs FP32 baseline 的 mAP 对比 |
| 推理延迟 | 10 / 50 / 100 条鱼场景下的单帧推理延迟 |
| 功耗 | idle / 推理 / PID 控制三种状态下的整机功耗 |
| 散热 | 持续推理 1 小时的核心温度曲线 |
| 平台对比 | RK3588 vs Jetson Orin Nano 的延迟与功耗对比 |
| 传感器精度 | pH / DO / Temp / NH3 与校准仪器对比 |
| 稳定性 | 7 天连续运行，监控掉线、内存泄漏、数据完整性 |

### 1.3 测试边界（明确不做）

- **不在 CI 中运行硬件测试**：本方案所有测试均需真实硬件，无法在 CI 环境执行。CI 仅保留 MockSensor/MockActuator 单元测试（T13 已覆盖）。
- **不使用模拟数据替代**：传感器精度与推理精度测试必须使用真实硬件读数与真实图像，禁止用模拟数据充数。
- **不覆盖云端功能**：本方案仅针对边缘端硬件，云端（TIER 2）与数字孪生（TIER 3）测试不在本方案范围。

## 4. RK3588 适配测试

### 4.1 YOLOv8n RKNN INT8 精度测试

**目的**：验证 INT8 量化后的模型精度损失是否在可接受范围内（< 0.3 mAP）。

**测试步骤**：
1. 使用 `tools/convert_yolo.py` 将 YOLOv8n 微调模型（FeedFishDatas 7.4K images）转换为 ONNX。
2. 从 ONNX 导出 FP32 baseline 模型，在测试集上计算 mAP。
3. 将 ONNX 转换为 RKNN INT8 量化模型（RKNN SDK 2.x）。
4. 在 RK3588 NPU 上运行 INT8 模型，对同一测试集计算 mAP。
5. 计算 mAP 损失 = FP32 mAP - INT8 mAP。

**通过标准**：
- mAP 损失 < 0.3。
- 若损失 ≥ 0.3，需检查量化校准集（增加代表性样本）或改用混合量化（部分层保留 FP16）。

**失败处理**：见第 8 节调整建议。

### 4.2 推理延迟测试（10 / 50 / 100 条鱼）

**目的**：验证不同鱼群密度下的单帧推理延迟，确认满足 < 15ms 目标。

**测试步骤**：
1. 准备三组测试图像/视频，分别含约 10、50、100 条鱼（真实拍摄，非合成）。
2. 通过边缘控制器加载 RKNN INT8 模型，对每组输入连续推理 1000 帧。
3. 记录每帧推理延迟（从输入到输出 Detection 的耗时），计算平均值、P95、P99。
4. 分别记录 10 / 50 / 100 条鱼三组数据。

**通过标准**：
- 三组平均延迟均 < 15ms（目标 < 10ms）。
- P95 延迟 < 20ms（允许偶发波动）。

**失败处理**：见第 8 节调整建议。

### 4.3 功耗测试（idle / 推理 / PID 控制）

**目的**：验证 RK3588 在三种运行状态下的功耗，确认符合散热与供电设计。

**测试步骤**：
1. 在 RK3588 供电回路串入功率计（或使用智能插座）。
2. **idle 状态**：边缘控制器启动但无推理、无控制输出，记录 10 分钟平均功耗。
3. **推理状态**：持续运行 YOLOv8n 推理（100 FPS），记录 10 分钟平均功耗。
4. **PID 控制状态**：推理 + 模糊 PID 控制 + 投喂电机 PWM 输出（50% duty），记录 10 分钟平均功耗。
5. 记录峰值功耗与平均功耗。

**通过标准**：
- idle ≤ 5W（设计值 4W）。
- 推理 ≤ 10W（设计值 8W）。
- PID 控制 ≤ 15W（设计值 12W）。

**失败处理**：见第 8 节调整建议。

### 4.4 散热测试（持续推理 1 小时）

**目的**：验证 RK3588 在持续满负荷推理下的热稳定性，确认被动散热片 + 温控风扇方案有效。

**测试步骤**：
1. 在 RK3588 核心散热片表面贴热电偶（或使用红外测温仪）。
2. 记录环境温度（配电箱内）。
3. 持续运行 YOLOv8n 推理 1 小时，每 5 分钟记录一次核心温度。
4. 观察是否触发降频（可通过 `cat /sys/class/thermal/thermal_zone*/temp` 或 RKNN 日志确认）。
5. 记录温度曲线与稳定温度。

**通过标准**：
- 核心温度稳定 < 70°C。
- 1 小时内无降频告警（环境温度 ≤ 50°C 额定范围）。
- 若环境温度 > 50°C，允许降频但需记录并评估。

**失败处理**：见第 8 节调整建议。

## 6. ESP32-S3 传感器精度测试

**目的**：验证 ESP32-S3 采集节点的传感器读数与校准仪器的一致性，确认满足精度要求。

### 6.1 测试准备

1. 完成传感器出厂校准（pH 3-point、DO 饱和空气法、浊度 Formazin）。
2. 准备校准仪器：实验室级 pH 计、溶氧仪、NIST 可追溯温度计、氨氮标准液。
3. 将传感器与校准仪器置于同一水体样本中，保证测量条件一致。

### 6.2 pH 精度测试（SEN0169）

**测试步骤**：
1. 准备 pH 4.00 / 7.00 / 10.00 三种标准液。
2. 将 SEN0169 探头与实验室 pH 计同时浸入标准液，等待稳定（60s）。
3. 记录 ESP32-S3 读数与校准仪器读数，各记录 10 次。
4. 计算偏差 = |ESP32 读数 - 校准仪器读数|，取最大偏差。

**通过标准**：最大偏差 ≤ 0.15（设计精度 ±0.11）。

### 6.3 溶解氧精度测试（SEN0237-A）

**测试步骤**：
1. 准备不同溶氧水平的水样（通过曝气/静置调节，覆盖 0-20 mg/L 范围）。
2. 将 SEN0237-A 探头与实验室溶氧仪同时浸入水样，等待稳定（90s）。
3. 记录 ESP32-S3 读数与校准仪器读数，各记录 10 次。
4. 计算偏差，取最大偏差。

**通过标准**：最大偏差 ≤ 0.25 mg/L（设计精度 ±0.22 mg/L）。

### 6.4 温度精度测试（DS18B20）

**测试步骤**：
1. 将 DS18B20 探头与 NIST 可追溯温度计置于同一水体。
2. 覆盖 5°C / 15°C / 25°C / 35°C 四个温度点（可通过恒温水浴调节）。
3. 每个温度点记录 10 次读数，计算偏差。

**通过标准**：最大偏差 ≤ 0.1°C（设计精度 ±0.08°C）。

### 6.5 氨氮精度测试（NH3 探头）

**测试步骤**：
1. 使用氨氮标准液配置 0.1 / 0.5 / 1.0 / 2.0 mg/L 四个浓度点。
2. 将 NH3 探头浸入标准液，等待稳定（120s）。
3. 记录 ESP32-S3 读数与标准液标称值，各记录 10 次。
4. 计算偏差，取最大偏差。

**通过标准**：最大偏差 ≤ 0.014 mg/L（设计精度 ±0.014 mg/L）。

### 6.6 传感器精度汇总表

| 参数 | 传感器 | 设计精度 | 测试通过标准 | 实测最大偏差 |
|------|--------|---------|-------------|-------------|

| 氨氮 | NH3 探头 | ±0.014 mg/L | ≤ 0.014 mg/L | 待填 |

## 7. 7 天连续运行稳定性测试

**目的**：验证边缘端全系统（RK3588 + ESP32-S3 + 执行器）在 7 天连续运行下的稳定性，确认无崩溃、无内存泄漏、数据完整。

### 7.1 测试环境

- 完整部署：RK3588 主控 + 2 个 ESP32-S3 传感器节点 + 摄像头 + 投喂电机 + 增氧泵 + 循环泵。
- 模拟真实投喂场景：每日定时投喂 3 次，模糊 PID 控制投喂电机。
- 网络环境：模拟弱网（MQTT 间歇性断开），验证离线缓冲与补传。

### 7.2 测试步骤

1. 部署完整系统，确认所有设备在线、数据正常上报。
2. 连续运行 7 天（168 小时），期间不人工干预。
3. 每日记录：
   - 设备心跳（`device/status` 主题，30s 间隔）。
   - 传感器数据完整性（对比 InfluxDB 接收点数 vs 理论点数）。
   - 内存占用（`free -m`，确认无泄漏）。
   - CPU / NPU 使用率。
   - 告警记录（`device/alarm` 主题）。
4. 第 3 天模拟 MQTT 断网 2 小时，验证 SQLite 本地缓冲 + 恢复后补传。
5. 第 5 天模拟传感器断线，验证跳过 + 告警。
6. 第 7 天结束，统计掉线次数、数据完整率、内存增长。

### 7.3 通过标准

| 指标 | 通过标准 |
|------|---------|
| 设备掉线次数 | < 1 次（计划内断网除外） |
| 数据完整率 | > 99%（断网期间本地缓冲，恢复后补传） |
| 内存泄漏 | 7 天内存增长 < 10%（排除缓存正常波动） |
| 崩溃/重启 | 0 次非计划重启 |
| 传感器断线处理 | 正确跳过 + 告警，不影响其他传感器 |
| 离线缓冲 | 断网 2h 数据完整补传，无丢失 |

**失败处理**：见第 8 节调整建议。

## 8. 失败处理与调整建议

### 8.1 YOLOv8n 精度损失 ≥ 0.3 mAP

| 可能原因 | 调整建议 |
|---------|---------|
| 量化校准集代表性不足 | 增加校准集样本（覆盖不同光照、鱼群密度、水质条件） |
| 模型对 INT8 敏感 | 改用混合量化（敏感层保留 FP16） |
| 输入预处理不一致 | 确认 INT8 与 FP32 使用相同的归一化 [0,1] 与 BGR→RGB 流程 |

### 8.2 推理延迟 ≥ 15ms

| 可能原因 | 调整建议 |
|---------|---------|
| NPU 未充分利用 | 确认使用 RKNN 三核 NPU 并行，检查 NPU 占用率 |
| 图像预处理瓶颈 | 优化 GStreamer 管线，4K→640×640 缩放是否在 NPU/GPU 侧完成 |
| 后处理耗时 | 优化 NMS（IoU=0.45）实现，考虑批量 NMS |
| 模型过大 | 确认使用 YOLOv8n（nano），非 s/m/l 版本 |

### 8.3 功耗超标

| 可能原因 | 调整建议 |
|---------|---------|
| 推理频率过高 | 确认推理频率（100 FPS 为上限，可降至 30 FPS 满足投喂决策） |
| 外设功耗 | 检查摄像头、4G dongle 等外设功耗，确认供电设计余量 |
| 电源转换效率 | 检查 DC-DC 转换效率，考虑更高效率电源模块 |

### 8.4 散热不达标（核心温度 ≥ 70°C）

| 可能原因 | 调整建议 |
|---------|---------|
| 散热片不足 | 增大散热片面积或改用主动散热（温控风扇提前开启阈值） |
| 配电箱通风不良 | 增加通风百叶或强制风道，配电箱安装于东/北侧避免阳光直射 |
| 环境温度过高 | 环境温度 > 50°C 时允许降频，评估是否需工业级宽温方案 |

### 8.5 传感器精度不达标

| 参数 | 可能原因 | 调整建议 |
|------|---------|---------|
| pH | 探头老化 / 校准漂移 | 重新 3-point 校准，检查探头寿命（12-18 月），必要时更换 |
| DO | 膜帽污染 / 填充液不足 | 清洁膜帽，补充填充液，重新饱和空气法校准 |
| Temp | 探头接触不良 | 检查 DS18B20 防水封装，重新安装 |
| NH3 | 探头老化 / 标准液失效 | 更换标准液，检查探头寿命（6-12 月） |
| 通用 | ADC 噪声 | 检查 ADS1115 滤波（中值 + EMA α=0.3），确认供电稳定 |

### 8.6 7 天稳定性不达标

| 可能原因 | 调整建议 |
|---------|---------|
| 内存泄漏 | 定位泄漏模块（推理/纹理/缓冲），修复后重测 |
| 数据丢失 | 检查 MQTT QoS 配置与本地缓冲逻辑，确认补传机制 |
| 设备掉线 | 检查供电稳定性、网络重连（指数退避 1s→30s） |
| 传感器断线误报 | 检查 HAL 健康监测阈值，确认断线判定逻辑 |
